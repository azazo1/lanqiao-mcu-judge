# NA10 第十届蓝桥杯单片机国赛

题目原文见 [problem/第十届决赛单片机设计与开发（第二部分）.pdf](problem/第十届决赛单片机设计与开发（第二部分）.pdf), 程序设计部分 70 分.

## 竞赛板配置

- IAP15F2K61S2 内部振荡器频率设置为 12MHz.
- 键盘工作模式跳线 J5 配置为 KBD 键盘模式.
- 扩展方式跳线 J13 配置为 IO 模式.

## 功能

- 超声波测距 (声速 340m/s, 范围 10cm-50cm) 与 DS18B20 温度测量.
- PCF8591 输出与测距结果对应的模拟电压.
- AT24C02 记录参数变动次数.
- 串口收发的数据召测功能.
- 数码管, 按键与 LED 指示灯完成人机交互.

## 显示格式

| 界面 | 提示符 | 内容 | 示例 |
| --- | --- | --- | --- |
| 温度数据 | `C` | 温度, 2 位小数, 占 4 位数码管 | `C   26.32` |
| 距离数据 | `L` | 距离, 单位 cm, 占 2 位数码管 | `L     30` |
| 变更次数 | `N` | 参数变动次数, 5 位数码管, 高位熄灭 | `N     2` |
| 温度参数 | `P` | 提示符 + 编号 1 + 参数值, 范围 0-99 | `P  1  30` |
| 距离参数 | `P` | 提示符 + 编号 2 + 参数值, 范围 0-99 | `P  2  35` |

## 按键

| 按键 | 功能 |
| --- | --- |
| `S13` 短按 | 数据界面与参数界面之间切换 (进入参数界面默认温度参数, 回数据界面默认温度数据) |
| `S12` 短按 | 数据界面下切换 温度数据/距离数据/变更次数, 参数界面下切换 温度参数/距离参数 |
| `S17` | 加键, 温度参数加 2 摄氏度, 距离参数加 5cm |
| `S16` | 减键, 温度参数减 2 摄氏度, 距离参数减 5cm |
| `S12` 长按 | 任何界面下把参数变动次数重置为 0 |
| `S13` 长按 | 任何界面下切换 DAC 启动与停止 |

其它要求: 长按判定为按下超过 1 秒; 按键消抖; 长按与短按功能互不影响.

## 存储, DAC 与串口

- 变动次数: 从参数界面退出时若参数发生变化则加 1, 保存在 E2PROM, 可记录 0-65535.
- DAC: 启动状态时 距离不超过距离参数输出 2V, 超过距离参数输出 4V; 停止状态固定输出 0.4V.
- 串口: 4800bps, 无校验, 1 位停止位; `ST\r\n` 返回 `$距离数据,温度数据\r\n`; `PARA\r\n` 返回 `#距离参数,温度参数\r\n`; 错误指令返回 `ERROR\r\n`; 响应不超过 500ms.

## LED 指示灯

| 指示灯 | 行为 |
| --- | --- |
| `L1` | 温度数据超过温度参数时点亮 |
| `L2` | 距离数据小于距离参数时点亮 |
| `L3` | DAC 启动状态点亮, 停止状态熄灭 |
| 其余 | 保持熄灭 |

## 初始状态

- DAC 处于启动状态.
- 数码管处于数据界面并显示温度数据.
- 温度参数 30 摄氏度, 距离参数 35cm.

## 性能要求

| 项目 | 要求 |
| --- | --- |
| 温度数据刷新时间 | <= 0.5s |
| 距离数据刷新时间 | <= 1s |
| 串口指令响应时间 | <= 500ms |

## 满分代码

- `src/driver/`: 数码管, 按键, LED, IIC, DS18B20, 超声波与串口驱动.
- `src/user/main.c`: 界面状态机, 参数管理, E2PROM 计数, DAC 输出与串口召测逻辑.
- `prj/na10.uvproj`: Keil 工程, 文件路径已改到本仓库的相对布局, 输出名为 `na10`.
- `prj/Objects/na10.hex`: 编译产物, 也是评测脚本的输入.

该代码来自上游的社区实现 (上游目录名标注为"脑测", 即作者未在硬件上验证), 不是 4T 已评过的满分代码, 采集时只做目录搬迁. 按"参考实现 (已知偏离题目)"看待: 评测脚本查出 DAC 输出条件写反, 变更次数界面提示符与初值不对, 串口 `PARA` 指令的参数顺序相反 (详见下节).

## 评测脚本

`judge/full.rhai` 按题目原文推导, 共 8 个评测点:

| 序号 | 评测点 | 题目出处 |
| --- | --- | --- |
| 1 | 上电处于数据界面显示温度两位小数, DAC 启动 (L3 亮, 距离 30cm 不超过参数 35cm 时输出 2V), 参数 30/35 | 4.1, 4.2-1, 4.6, 4.7, 4.8 |
| 2 | `S12` 依次切换 温度/距离/变更次数 三个数据界面, 提示符与格式正确 | 4.2-1, 4.3-1 |
| 3 | 参数界面显示 `P  1  30` 与 `P  2  35`, 温度参数 ±2 摄氏度, 距离参数 ±5cm | 4.2-2, 4.3-1 |
| 4 | 参数变化并退出参数界面后变动次数加 1 并写入 E2PROM, 参数未变不计数, 长按 `S12` 清零 | 4.4, 4.3-2 |
| 5 | DAC 启动时 2V/4V 与距离参数的关系, 长按 `S13` 停止后输出 0.4V, 再次长按恢复 | 4.3-2, 4.6 |
| 6 | `L1` 温度超参数, `L2` 距离小于参数, `L3` 启动状态, 其余指示灯熄灭 | 4.7 |
| 7 | 串口 `ST` 返回 `$距离,温度`, `PARA` 返回 `#距离参数,温度参数`, 错误指令返回 `ERROR` | 4.5 |
| 8 | 刷新与响应时间: 温度刷新 <= 0.5s, 距离刷新 <= 1s, 串口响应 <= 500ms (实测 340ms / 40ms / 30ms) | 4.1 |

运行方式:

```shell
just judge-sample na10
```

当前回归结果: 4 项通过, 4 项失败 (第 1, 2, 5, 7 项, 见下). 第 8 项的三条时间要求都满足, 说明该实现的采集与串口响应速度没有问题, 失败集中在功能与协议细节上.

## 评测脚本发现的实现问题

| 位置 | 题目要求 | 实测 | 说明 |
| --- | --- | --- | --- |
| DAC 输出 | 距离不超过距离参数输出 2V, 超过输出 4V | 距离 30cm (参数 35cm) 输出 4V, 距离 50cm 输出 2V | 两个条件对应的电压写反了 |
| 变更次数界面 | 提示符为 `N` | 显示 `H` | 该实现的段码表 (`src/driver/seg.c`) 只有 `0`-`9`, 空, `-`, `C`, `L`, `q` (`0x89`), `P` (`0x8c`) 这些字形, 没有 `N`; 计数界面复用了 `0x89`, 这个字形在数码管上呈 H 形, 因此与题目要求的 `N` 不符 |
| 变更次数初值 | 变动次数初值为 0 | E2PROM 清零后仍显示 255 | 计数变量或读取方式与 E2PROM 中的数值不一致 |
| 串口 `PARA` 指令 | 返回 `#距离参数,温度参数` | 返回 `#30,35`, 即温度参数在前 | 参数顺序与题目要求相反 |

已通过的评测点 (参数加减, 变动次数计数与长按清零, LED 指示逻辑, 温度与距离显示, `ST` 指令格式) 说明该实现在这些方面与题目一致.
