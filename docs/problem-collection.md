# 蓝桥杯真题收集与评测脚本进度

本文件记录蓝桥杯单片机设计与开发赛道省赛, 国赛各场次的真题, 满分代码与评测脚本的收集情况, 以及当前的验证状态. 它是 `samples/` 的工作清单与总账.

范围说明: 目标平台是 IAP15F2K61S2 + 四梯竞赛板, 因此以第十届及以后的省赛, 国赛为主; 更早届次的题目只做原题归档 (见下文"原题归档"), 不建 sample.

## 命名与目录约定

一场真题对应 `samples/` 下的一个目录:

- 国赛: `na<届>`, 例如 `na15`, `na16`.
- 省赛: `pa<届>`, 例如 `pa14`, `pa15`.
- 同一届同一赛项有多场次时加 `-1`, `-2`: 例如 `pa12-1` (第十二届省赛第一场), `pa16-1`.
- 同一届同一赛项有多组别时加 `u` (大学组) 与 `v` (职业院校组): 例如 `na14u` 与 `na14`, 两个 sample 各自独立.
- 自编题: `la<序号>`, 例如 `la17`, 不是真题.

单个 sample 的目录结构:

| 路径 | 内容 |
| --- | --- |
| `problem/` | 原题文件, 直接保存收集到的 PDF 或图片, 不做改动 |
| `src/driver`, `src/user` | 收集到的满分代码, 只做目录搬迁, 不改代码逻辑 |
| `prj/` | Keil 工程与编译产物, `prj/Objects/<sample>.hex` 是评测输入 |
| `judge/` | 评测脚本, 按题目原文推导, 不参考实现代码 |
| `README.md` | 题目整理, 评测点对照表与验证结果 |

`samples/<id>/prj/Objects/` 下必须只有一个 hex, 这是 `just judge-sample` 的前提.

## 单场真题的制作流程

1. 取原题放入 `samples/<id>/problem/`. 扫描件或图片题目先用本地 OCR 转成文本 (见下文"扫描件与图片题目").
2. 取满分代码: `src/driver` 与 `src/user` 归位, Keil 工程放 `prj/`, 并把工程内的文件路径改到本仓库的相对布局.
3. `prj/Objects/<id>.hex` 用上游编译产物; 工程里的输出名与 sample 名保持一致, 避免重新编译后出现第二个 hex.
4. 读原题, 推导功能点, 显示格式, 性能要求与初始状态, 写入 `README.md`.
5. 按题目推导评测脚本, 每个评测点写成 `ckpt(...)`, 注释说明题目出处.
6. 用该 hex 回归. 通过说明评测点推导与题目一致; 失败则先分辨"脚本问题"还是"实现偏离题目", 后者写入 README 的"评测脚本发现的实现问题".

## 扫描件与图片题目

省赛第十四届 (图片) 与第十一届, 第十六届省赛第一次 (扫描件) 的题目都按下面的流程整理:

1. `pdftoppm -r 300 -png` 渲染, 或直接使用题目图片.
2. 本地 Apple Vision OCR 工具 (源码 `.tmp/collect/ocr/ocr.swift`, 编译为 `ocr`, 语言 zh-Hans + en-US) 逐页识别, 按坐标排序输出纯文本.
3. 识别结果作为 `problem/题目OCR文本.txt` 保存, 评测点按这份文本推导; 扫描件里只有图形的数码管版式 (例如各界面图) 需要额外核对, 无法确认的地方按范围断言并在 README 里注明.

整个过程不需要把图片读进上下文.

## 偏差结论的复核

"参考实现 (已知偏离)" 这类结论有过误判 (脚本读错界面把正确固件判成错误, 见 `pa15`), 因此每条结论都逐一复核过判定依据:

| sample | 偏差结论 | 复核方式与结果 |
| --- | --- | --- |
| `na10` | 变更次数提示符不是 `N`, 计数初值 255, DAC 条件写反, `PARA` 字段顺序相反 | 读该实现的段码表确认它没有 `N` 字形 (复用 `0x89` 的 H 形); DAC 与串口两项按两个方向分别实测, 结论成立 |
| `na11` | 温度与参数界面标识符不是 `C`/`P`/`E` | 读段码表确认它只有 F/H/S 三个字母, 结论成立 |
| `na12` | 定时模式下距离报警 `L5` 不点亮 | 把测距放在参数中心 (参数 40cm, 测距 39cm) 观察 8 秒以上, `L5` 全程为灭, 结论成立 |
| `na14` | 记录与 DAC 输出功能未实现 | 固定距离与连续变化距离两种场景, 记录后按输出键 DAC 恒为 0, 结论成立 |
| `na16` | 504 异常状态未进入 | 与 4T 平台原始记录 (该项判"错误") 一致, 结论成立 |
| `pa11-1` | 上电不读回 EEPROM 参数 | 预置特征字 `0xAA` 与 12/34/56 后复位, 显示仍是初值 (地址 255, 满量程 5.5), 结论成立 |
| `pa15` | (原) 最大频率回显异常 | **误判**: 脚本在断言时才读显示, 读到的是时间回显; 修正后 8/8 全通过 |
| `pa15-2` | 温度突变报警 `L4` 未触发 | 结论细化为"首次突变能按要求闪烁 3 秒, 连续多次突变后不再触发", 仍属实现偏离 |
| `pa16-1` | 光强等级 `N3` 不可达 | 电压上升与下降两个方向各扫描一遍 (每点保持数秒), `N3` 从未出现, 结论成立 |
| `pa17` | 上电不读回 EEPROM 参数, 串口应答时间与显示不一致, 工厂模式 `L2` 不闪烁 | EEPROM 项用不同数值预置确认; 串口项实测显示正确而应答为 `00:00` (并记录等待数秒后曾返回正确值); `L2` 用 100ms 间隔连续观察 6 秒全灭, 结论成立 |

## 仿真器缺口与处理

收集过程中发现的问题按"是不是仿真器的错"分类处理: 属于仿真器缺口的修仿真器并在这里留痕, 属于实现偏离题目的写进对应 sample 的 README.

| 缺口 | 场次 | 处理 |
| --- | --- | --- |
| 段码解码表缺少 `A` (`0x77`) | `pa12-1` | 补入默认解码表 |
| 段码解码表缺少 `N` (`0x37`) 与 `U` (`0x3E`) | `pa12-2` | 补入默认解码表 |
| 段码解码表缺少 `n` (`0x54`) | `pa11-1` | 补入默认解码表 |
| 段码解码表缺少单段映射 `=` (`0x01`, a 段) 与 `_` (`0x08`, d 段) | `na12` | 补入默认解码表 |
| 电机变速后的位置与题目公式不符 | `na15` | 已修复: 位置轨迹诊断显示固件速度符合公式 (600Hz 段 34.4cm/s, 4000Hz 段 172cm/s), 但变速后需要一个测频窗口才能把新频率体现到速度上, 位置整体落后理想积分约 0.25 秒 (等效 40cm). 已在 `judge/4t.rhai` 的 `speed_segments_distance_window` 里为每个变速边界给下限留出 0.25 秒的过渡余量, 第 58 项由失败转为通过 |
| 电压读数在正确值与 2.50V 之间交替 | `pa10` | 已定位为固件行为, 不是仿真器缺口: 仿真器的 PCF8591 模型符合手册语义 (一次读返回上一次转换结果, 上电初值为 `0x80` 即 2.51V, 并有单测 `first_read_returns_power_on_default_then_latest_conversion` 覆盖), 而固件 `Ad_Read` 在写控制字节 `0x43` 之后只读一次, 因此会显示到上一次转换值; 题目只要求 `S7` 控制显示开关, 评测脚本按界面格式判定 |
| 数据刷新时间略超上限 (电压 520ms > 0.5s) | `pa10` | 已定位: 用轮询测量电位器电压刷新耗时, 实测 520ms, 超出题目 4.1-4 的 0.5 秒上限 20ms; 与"读数在两个值之间交替"那条无关 (显示会收敛, 只是稍慢). 评测脚本按题目上限断言, 因此该项判为不通过 |

写评测脚本时值得记住的两条经验:- 变速/换挡类题目里, 固件需要先测到一个完整周期的输入信号才能改变输出, 所以按公式投影位置或速度时要在变速边界给下限留出过渡时间 (`na15` 实测约 0.25 秒), 否则会把正确的固件判成错误.
- 采样实现普遍带滑动滤波, 改变输入后要等若干个刷新周期才稳定; 采集等待量按题目刷新要求留出余量 (通常 2 秒左右).
